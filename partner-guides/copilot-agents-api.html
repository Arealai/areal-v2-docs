Copilot Agents API: Integration Guide

How to list a loan's Copilot agents, read their status, read their tasks and change those tasks through the Areal API. These are the same endpoints the Areal dashboard uses.

Overview

Copilot runs natural-language checks and automations against the documents and data of a mortgage loan. An agent is a named set of tasks. Each task holds a prompt, and when the prompt is saved Areal turns it into a step-by-step plan. Running a task executes that plan against one loan and stores a result for that loan.

This guide covers four integration jobs:

1. List agentsGET /copilot/task-group/
2. Pull agent statusGET /copilot/task-group/ or GET /copilot/task-group/{id}/
3. Pull tasks for each agentGET /copilot/task-group/{id}/tasks/
4. Modify tasks for each agentPATCH /copilot/task/{id}/ and related endpoints

Concepts

The dashboard and the API use different names for some things. This guide uses the dashboard names in prose and the API names in code.

Dashboard termAPI termMeaning
LoanSession (session_id)All documents for one loan in your organization. Agents are defined once for the whole organization, but their status and results are always per loan, so almost every call takes a session_id.
AgentTask group (task_group_id)A named set of tasks. It may also have one starting condition (a gate task that must pass before the other tasks run) and one post-run action (a task that runs after the others finish).
TaskTask (task_id)One prompt, the plan generated from it, and its latest result on the loan.
Generated actionsresults.planThe numbered steps Copilot built from the prompt.
Run / executionresults (Task Execution Result)The latest execution of a task against one loan. Only the latest run per task and loan is kept.
A task has two different statuses. Don't mix them up. status is the task's configuration state: active or draft. Only active tasks run when the whole agent runs. results.status is the outcome of the latest run on this loan: pending, success, failed, n/a, or null if it has never run.

Basics

Base URL

EnvironmentBase URL
UAThttps://uat-api.v2.areal.ai/api/v2

All paths in this guide are relative to the base URL. Requests and responses are JSON. Send Content-Type: application/json on requests that have a body. Paths end with a trailing slash; keep it.

Full request and response schemas for every endpoint in this guide are in the OpenAPI file that comes with it, copilot-agents-openapi.json.

Authentication

For server-to-server integrations, use an API key. Areal issues one per integration user. Send it on every request in either of these headers:

Authorization: Bearer <api_key>      # recommended
key: <api_key>

The key acts as one user in your organization. That user can only see agents, tasks and loans that belong to its organization.

Errors

Error responses have a JSON body with a message field:

{ "message": "Unauthorized access attempt to session" }
StatusWhen it happens
400A business rule failed, for example creating a second starting condition, or overriding a task that has not failed.
401No valid credentials were sent.
403The agent, task or loan belongs to another organization.
404The id doesn't exist or isn't a valid UUID.
409The task can't run yet. Usually an Encompass loan-lock retry is already scheduled for it (see results.next_retry_at).
422The request body or query parameters don't match the schema. The response lists the invalid fields.
5xxUnexpected server error. Safe to retry with backoff for GET requests and run requests.

Finding the loan's session_id

Every call below needs the Areal session_id of the loan. If you only have your LOS loan number or GUID, search for it:

GET/sessions/?search={loan_number_or_name}

search matches the loan's name and its external references, such as the LOS loan number and GUID. Use objects[].id from the response as session_id.

      // ... more loan fields
    }
  ]
}

1. List agents

GET/copilot/task-group/?session_id={session_id}

Returns every agent in your organization, newest-updated first, with a status summary for the given loan. This is the request behind the dashboard's Agentic Executions table on a loan's Copilot tab.

Query parameterRequiredDescription
session_idRecommendedThe loan to compute status for. Without it every agent comes back as no-run with zero counts.

The response isn't paginated, and filtering and sorting are done by the client. In the list response, tasks is always an empty array, and starting_condition and post_run_action are always null. To get them, use agent detail and tasks.

2. Pull agent status

An agent's status is always relative to one loan. Use the list call above to get the status of every agent on a loan in one request. To get one agent with its starting condition and post-run action, use agent detail.

Status values

statusMeaning
all-passAt least one task succeeded and none failed. Tasks with n/a are ignored.
partialSome tasks succeeded and some failed.
failedAt least one task failed and none succeeded.
not-applicableThe starting condition ran and failed, so the agent's tasks don't apply to this loan. This is also returned when every task's result is n/a.
no-runNo finished results yet. Either the agent has never run on this loan, its starting condition hasn't run yet, or its tasks are still pending.

Areal applies these rules in order, and the first one that matches wins:

  1. The agent has a starting condition that hasn't run on this loan: no-run.
  2. The starting condition failed: not-applicable.
  3. No task has a success, failed or n/a result: no-run.
  4. Every task is n/a: not-applicable.
  5. At least one success and at least one failure: partial.
  6. At least one success and no failures: all-pass.
  7. At least one failure and no successes: failed.
A run in progress is not a status of its own. While tasks are running they count as pending, and the agent status is computed only from tasks that have finished. If you start a new run, the agent keeps showing the previous status until new results come in. To tell whether a run is still going, check the tasks themselves, as described in Tracking a run.

Agent detail

Tracking a run

Running an agent or a task returns right away, and the work continues in the background. A run usually takes from a few seconds to a few minutes, depending on how many steps the plan has and whether it writes to your LOS. To follow a run:

  1. Start the run (see Run a task or agent).
  2. Poll GET /copilot/task-group/{task_group_id}/tasks/?session_id=… every 5 to 10 seconds.
  3. The run is finished when no active task has results.status = pending.
  4. Read the agent status again with the list or detail call.

If the agent has a starting condition, poll agent detail first. When starting_condition.results.status becomes success, Areal starts the other tasks; if it becomes failed, the other tasks don't run. Set an overall timeout on your polling (for example 15 minutes) and back off when you get 5xx responses.

Real-time updates The dashboard gets live COPILOT_TASK_CREATED, COPILOT_TASK_UPDATED and COPILOT_TASK_DELETED messages over a WebSocket. That connection is tied to a browser login session, so server-to-server integrations should poll as described above.

ValueMeaning

failedThe check failed or the action couldn't complete. See error_message and execution_results.

A single task

GET/copilot/task/{task_id}/?session_id={session_id}

Returns one task object in the same shape as above. Use it to poll one task after running it, or to read the starting condition or post-run action by id.

Edit a task's name or prompt

PATCH/copilot/task/{task_id}/?session_id={session_id}
Body fieldTypeDescription
namestring, optionalNew display name.
promptobject, optionalNew prompt in formatted prompt format. Areal generates a new plan from it.

Leave out any field you don't want to change. session_id is required: Areal uses that loan as context when it generates the plan, and the response contains the task's result on that loan.

curl -s -X PATCH "https://uat-api.v2.areal.ai/api/v2/copilot/task/$TASK_ID/?session_id=$SESSION_ID" \
  -H "Authorization: Bearer $AREAL_API_KEY" \
  -H "Content-Type: application/json" \
  --max-time 120 \
  -d '{
    "name": "Note is fully signed",
    "prompt": {
      "type": "doc",
      "content": [{
        "type": "paragraph",
        "content": [
          { "type": "text", "text": "Check that every borrower signed every signature page in " },
          { "type": "mention", "attrs": { "type": "template", "id": "3f2e1d0c-...", "label": "Note" } }
        ]
      }]
    }
  }'

Returns the updated task object.

Changing the prompt is slow and doesn't re-run the task. Plan generation happens inside the request and can take up to about 90 seconds, so set your client timeout to at least 120 seconds for this call and for create. The response shows results.status as pending to mark the old result as out of date, but nothing is re-run. Until you run the task again, later reads still return the result from the old prompt.

Activate or deactivate a task

POST/copilot/task/{task_id}/change-status/
{ "status": "active" }   // or "draft"

Only active tasks run when the whole agent runs, whether manually or automatically. A draft task can still be run on its own with the task run endpoint. New tasks start as draft. The response is {"message": "Task activated"} for both values; read the task again to confirm its state.

Returns the new task object with its generated plan. The task starts as draft. Its result on this loan shows pending, but nothing runs until you start it. To include it when the whole agent runs, activate it. Then run it to get a result.

Delete a task

DELETE/copilot/task/{task_id}/

Permanently removes the task and its results on every loan. Returns {"message": "Task removed"}. This can't be undone. To stop a task from running but keep it, set it to draft instead.

Run a task or a whole agent

One task

POST/copilot/task/{task_id}/execute/

Runs the task on the loan, whether it is active or draft.

Whole agent

POST/copilot/task-group/{task_group_id}/execute/

If the agent has a starting condition, Areal runs that first, and the active tasks run only if it succeeds. Otherwise every active task runs.

{ "session_id": "6f1c2b0e-3a7d-4c55-9a1e-2b8f0d4e9c11" }

Both return {"message": "ok"} right away, and the run continues in the background. When you run a single task, its results.status changes to pending before the response is sent. Follow the run as described in Tracking a run.

A single-task run returns 409 while an Encompass lock retry is scheduled for that task (results.next_retry_at is set). Wait until that time, or until the retry finishes, then try again.

Tasks that write to Encompass If results.is_encompass_update_task is true and results.is_encompass_update_accepted is false, the dashboard asks the user to confirm before running the task, because the run will write fields to the Encompass loan. Your integration should get the same confirmation from a person before it runs such a task.

Override a failed result

POST/copilot/{task_id}/suppress/

Marks a failed result as a false positive on one loan. This is the dashboard's Override status menu. Only the reported status changes; the step results and error message are kept.

Body fieldTypeDescription
session_idstringThe loan.
statussuccess | n/aThe status to report instead of failed.
descriptionstring, optionalWhy you're overriding it. Stored as suppressed_reason.
unsuppressbool, default falseSet to true to remove an override.
// Override
{ "session_id": "6f1c…", "status": "n/a", "description": "Co-borrower removed from the loan" }

// Remove the override. "status" is still required; send the task's current status.
{ "session_id": "6f1c…", "status": "n/a", "unsuppress": true }

Overriding is only allowed when the latest result is failed, and removing an override is only allowed when one exists. Otherwise the call returns 400. Either way, the calling user becomes the task's assigned_user on that loan.

Removing an override doesn't bring back the original failure. The dashboard runs the task again right after it removes an override, and your integration should do the same.

Assign a user to a task result

POST/copilot/task/{task_id}/assign_user/
{ "session_id": "6f1c…", "user_id": "c0ffee00-…" }   // user_id: null to unassign

Sets who is responsible for the task's result on this loan. The assigned user gets an email notification. user_id must be a user in your organization; list them with GET /profiles/users/ and use users[].id. The task needs a result on this loan first, so run it at least once; otherwise the call returns 400.

Prompt format

When you create or edit a task, send the prompt as a formatted_prompt document. It is a rich-text tree made of paragraphs, where each paragraph contains plain text and mentions. A mention is a reference to a document type, a field or an external system. Areal uses mentions to choose which loan documents and data a task reads, so put the documents and fields a task depends on in mentions, not in plain text.

{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "Extract account balance from " },
        { "type": "mention", "attrs": { "type": "template", "id": "<template id>", "label": "Bank Statement" } }
      ]
    }
  ]
}

Each mention's label is display text. type and id tell Areal what the mention refers to. Look up ids with the endpoints below:

attrs.typeRefers toWhere to get id
templateA document type (for example Note, Closing Disclosure)GET /resources/templates/?search=… → objects[].id
componentA field extracted from a document typeGET /resources/templates/{template_id}/components/ → objects[].id
loan_infoA loan-level attributeGET /resources/loan_infos/?search=… → objects[].id
encompassAn Encompass fieldThe Encompass field id, for example 4000 or CX.ISECLOSING
byteA Byte fieldGET /resources/byte_fields/
meridianlinkA MeridianLink fieldThe MeridianLink field id
selectorA document selector, such as which version of a document to useGET /resources/selectors/
emailAn email template to sendGET /profiles/admin/organization/email_templates/
loan_contactsA loan contact by role. The email address is looked up on the loan at run time.GET /copilot/loan-contact-roles/ → roles[].key (for example closer)
docusignA DocuSign templateGET /resources/docusign_templates/

The read-only prompt field on a task shows how Areal reads the formatted prompt, for example Extract account balance from [[/template/Bank Statement]]. Use it to check that your mentions were recognized.

End-to-end example (Python)

This script finds a loan, lists its agents and their statuses, lists each agent's tasks, changes one task, runs the agent and waits for the run to finish.

import os, time, requests

BASE = "https://uat-api.v2.areal.ai/api/v2"
api = requests.Session()
api.headers["Authorization"] = f"Bearer {os.environ['AREAL_API_KEY']}"


def get(path, **params):
    r = api.get(f"{BASE}{path}", params=params, timeout=30)
    r.raise_for_status()
    return r.json()


# 0. Loan number -> session_id
session_id = get("/sessions/", search="1000123456")["objects"][0]["id"]

# 1 + 2. Agents and their status on this loan
agents = get("/copilot/task-group/", session_id=session_id)["task_groups"]
for a in agents:
    print(a["name"], a["status"], f"{a['tasks_completed']}/{a['tasks_total']} passed")

# 3. Tasks of each agent (paginated)
def all_tasks(agent_id):
    page, out = 0, []
    while True:
        body = get(f"/copilot/task-group/{agent_id}/tasks/",
                   session_id=session_id, pageIndex=page, pageSize=100, sort="name.asc")
        out += body["objects"]
        if len(out) >= body["meta"]["totalCount"] or not body["objects"]:
            return out
        page += 1

agent = agents[0]
tasks = all_tasks(agent["id"])
for t in tasks:
    print("  ", t["name"], t["status"], t["results"]["status"])

# 4. Modify: rename a task and make sure it is active
task = tasks[0]
api.patch(f"{BASE}/copilot/task/{task['id']}/", params={"session_id": session_id},
          json={"name": "Note is fully signed"}, timeout=120).raise_for_status()
api.post(f"{BASE}/copilot/task/{task['id']}/change-status/",
         json={"status": "active"}, timeout=30).raise_for_status()

# Run the whole agent on this loan, then wait until no active task is pending
api.post(f"{BASE}/copilot/task-group/{agent['id']}/execute/",
         json={"session_id": session_id}, timeout=30).raise_for_status()

deadline = time.time() + 15 * 60
while time.time() < deadline:
    time.sleep(10)
    active = [t for t in all_tasks(agent["id"]) if t["status"] == "active"]
    if not any(t["results"]["status"] == "pending" for t in active):
        break

detail = get(f"/copilot/task-group/{agent['id']}/", session_id=session_id)
print("Agent status:", detail["status"])

For an agent with a starting condition, a run started from here may stop at the condition. In that case no task becomes pending and the loop ends on its first check. Read detail["starting_condition"]["results"]["status"] to see whether the agent went on to run its tasks.
